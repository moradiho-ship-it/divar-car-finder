# Build a Production-Ready Divar Car Finder with Django, React, Supabase, and Telegram

You are a senior full-stack software engineer and product designer.

I want you to build a complete production-ready web application called **Divar Car Finder**.

The product allows a user to define the exact type of car they are looking for. The system periodically checks Divar for newly published car listings matching those criteria. When a matching listing is discovered, the system stores it and immediately sends a detailed notification through a Telegram bot.

The application must include a highly polished Persian RTL admin dashboard.

Do not only give me an architecture description. Implement the application step by step and create all required source files, migrations, APIs, frontend pages, background jobs, crawler modules, configuration files, Docker files, and documentation.

## 1. Main Product Goal

The user should be able to create one or multiple car search profiles.

Example search:

* Brand: Toyota
* Model: Camry
* Minimum year: 2018
* Maximum year: 2023
* Minimum price: 1,500,000,000 IRR
* Maximum price: 3,000,000,000 IRR
* Maximum mileage: 80,000 km
* City: Tehran
* Transmission: Automatic
* Body condition: No paint
* Color: White or Black

Every hour, the backend should search Divar.

If a new advertisement matches the user's conditions:

1. Save the listing in the database
2. Prevent duplicate listings from being inserted
3. Associate the listing with the matching search profile
4. Send the listing to the user's Telegram account
5. Store the Telegram delivery status
6. Show the listing in the web dashboard

The architecture must allow the crawling frequency to be changed later.

## 6. Matching Engine

Do not rely only on the search URL.

Create a second server-side matching layer.

For every retrieved listing calculate whether it matches the SearchProfile.

Implement a reusable service such as:

```python
match_listing(search_profile, listing)
```

Support:

* exact filters
* ranges
* multiple allowed values
* required keywords
* excluded keywords
* missing data handling

Return:

```json
{
  "matched": true,
  "score": 92,
  "matched_fields": {},
  "failed_fields": []
}
```

Use a configurable match score between 0 and 100.

Hard filters such as price limits should normally disqualify a listing.

Soft filters can influence the match score.

Keep this logic independent from the crawler.

## 7. Divar Crawler

Implement the crawler carefully.

Do not tightly couple parsing logic with business logic.

Separate these responsibilities:

```text

```

Create a normalized Python data structure for crawler results.

```python
class NormalizedListing:

    price: int | None

    mileage: int | None
    city: str | None
    description: str | None

```

Use resilient extraction strategies.

Add:

* timeouts
* retries
* exponential backoff
* request throttling
* reasonable random delays
* structured logging
* error handling
* HTML or payload validation
* duplicate protection
* transaction safety

Respect the target service's applicable terms, access rules, rate limits, and robots or technical restrictions.

Do not attempt to bypass CAPTCHAs, authentication controls, anti-bot protections, or other access restrictions.

If Divar provides a public endpoint suitable for retrieving listing information, isolate its usage in the provider adapter.

If the website structure changes, parsing errors must not crash the entire background worker.

Store useful parsing errors for debugging.

```text
    ↓

    ↓
```

Use Redis or database locking so two workers do not crawl the same profile simultaneously.

## 9. Duplicate Detection

Duplicate notifications must never be sent.

Use several levels of protection.

Primary:

```text
provider + external_id
```

Additional safeguards:

* canonical URL
* SearchMatch unique constraint
* Notification unique constraint where appropriate

The same listing can match multiple search profiles.

However, avoid sending redundant Telegram notifications to the same user when appropriate.

Implement an intentional deduplication policy and document it.
